# Markdown への変換

get-md は、抽出した HTML を [htmd](https://crates.io/crates/htmd) で Markdown に変換したあと、相対 URL の解決と表の圧縮を行います。このページでは、その後処理がリンク・コード・表をどう扱うかを説明します。処理は CommonMark のブロック構造に沿って判定するので、コードの中などにある、Markdown の構文に見えるだけの文字列は変更しません。

## 不要な要素の除去

- **除去する要素**: 変換の前に `script`・`style`・`noscript`・`svg` の要素を取り除く

## URL の解決

- **URL の解決**: レンダリング後のドキュメントの基準 URL (`<base href>` を含む) で、相対 URL を絶対 URL に変換する
- **コード領域を保護した URL の解決**: Markdown のリンクを解決するとき、インラインコード、コードフェンス、CommonMark のインデントコードブロック、ブロッククォート内のコードブロックの中は変更しない
- **Markdown リンクへの対応の強化**: `<...>` 形式 (スペースを含む URL) のリンク先を解決し、実際の Markdown リンク構文ではない単独の `](` は変換しない
- **壊れたリンクへの耐性**: 閉じ `)` が見つからないリンク候補や、閉じ `>` がない壊れた `<...>` のリンク先があっても走査を打ち切らず、ネストしたリンクを含む後続の正常なリンクを解決する
- **段落の境界を守るリンク解析**: 未閉鎖の `[` やインラインのバッククォートを、段落の境界 (ブロッククォート記号だけの空行を含む) やコードブロックの境界の先にある区切りと結合しない。単一の soft break を含む正規のリンクテキストは維持する。壊れたリンクの閉じ区切りの探索も、ブロッククォート記号だけの空行で打ち切る
- **山括弧のリンク先の括弧**: `<...>` の中の `)` をリンクの終端と誤認しない
- **山括弧の中のエスケープ**: `<...>` の中の `\>` を終端と誤認せず、URL の解決でも文字 `>` として正しく扱う
- **エスケープした `<`**: 通常の形式のリンク先にある `\<` を山括弧形式の開始と誤認せず、文字 `<` として扱う。URL の解決ではパーセントエンコーディングして出力する
- **エスケープした括弧**: `\(` と `\)` を含むリンク先の閉じ括弧を正しく解釈し、URL の解決でも括弧を壊さない
- **釣り合わない括弧**: 解決後の URL に釣り合わない `(` や `)` が含まれる場合は `<...>` 形式で出力し、Markdown のリンクが壊れるのを防ぐ
- **リンク先の引用符**: 通常の Markdown のリンク先にある引用符やアポストロフィを壊さない
- **空のリンク先と title**: `[text]( "title")` や `[text]( 'title')` のような、リンク先が空で title だけを持つ有効な構文で、title を URL と誤認せずに保持する
- **エスケープした空白**: 通常の Markdown のリンク先にある `\ ` を title の区切りと誤認せず、URL の解決では空白として正しく扱う
- **リンク先の前の空白**: Markdown のリンク先で URL の直前に空白がある有効な構文でも、相対 URL を正しく解決する

## コードブロックとインラインコード

- **CommonMark に準拠したフェンスの判定**: 開始と終了のフェンスは、外側のリスト項目の内容のインデントを基準に最大 3 スペースまでを許容し、それを超えるバッククォートの行はインデントコードとして保持する。リストマーカーと同じ行から始まるフェンスも認識し、リストやブロッククォートが終わるとフェンスの状態を正しく閉じる。info string 付きの行 (例: ` ```rust `) も閉じフェンスとして扱わない。表の圧縮も同じブロックの分類を使うため、これらのフェンスの中にある表のようなコードは保持し、フェンスが閉じた後に圧縮を再開する
- **リスト構造を考慮したインデントコードの判定**: インデントコードブロックは、外側のリスト項目の内容のインデントを基準に判定する。そのため、3 段以上ネストしたリスト (HTML から Markdown への変換では 4 スペース以上のインデントになる) の中の相対リンクも解決する。リスト項目の中の本物のインデントコードは変換しない。`* * *` のようなテーマ区切りもリスト項目と誤認しない
- **未閉鎖のバッククォート**: 閉じていないインラインのバッククォートは文字として扱い、その後ろの Markdown リンクの解決を妨げない。閉じバッククォートの先読みは、リストマーカーと同じ行から始まるフェンスでも打ち切る
- **線形時間のバッククォートの照合**: 段落とフェンスの境界の中で、同じ長さのバッククォートの列を事前に索引化し、未閉鎖の列が多い文書でも後方の繰り返し走査を防ぐ
- **複数行にわたるインラインコード**: 改行をまたぐインラインコードが閉じた後も物理的な行頭の状態を正しく追跡し、同じ行にあるフェンスやインデントに見えるテキストのせいで、後続のリンクを見落とすことを防ぐ

## 表

- **表の圧縮**: Markdown の表の不要なパディングを除去する。コードフェンスの中と、`--` や `:` のようなセパレータに見えるデータのセルは保持する
- **エスケープしたパイプ**: 表の圧縮で、セルの中の `\|` を区切り文字と誤認しない。末尾の区切りパイプを省略した行でも、最後のセルの `\|` を保持する
- **インラインコードの中のパイプ**: 表の圧縮で、セルのインラインコードの中にある `|` をセルの区切りとして扱わず、コードの内容を保持する
- **インデントコードブロック**: 4 スペース以上インデントされた行は CommonMark のインデントコードブロックとして表の行に含めず、先頭のインデントとセルの中の空白を保持する
